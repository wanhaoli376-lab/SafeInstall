# v0.2.0-alpha.1 release security review

Date: 2026-08-12

Scope: archive loading, GitHub loading, GUI presentation, report export, PyInstaller packaging,
release dependency resolution, GitHub Actions permissions, checksums, SBOM generation, and GitHub
Release publication.

## Outcome

No blocking issue remains after two confirmed release-validation gaps were fixed. The review did not
find a path from scanned target content to code execution, dependency installation, AI enablement,
release credentials, or publication permission.

## Fixed validation gap: unsafe members in a release ZIP

Classification: confirmed validation gap in the release pipeline; not a target-scanning
vulnerability. Exploitation required a malformed or substituted build artifact.

```text
Source
Malformed or substituted Windows/macOS build ZIP
↓
Path
download-artifact → release ZIP validation → draft upload
↓
Security boundary
An official release archive must extract only inside SafeInstall/ or SafeInstall.app/
↓
Impact
A traversal member or escaping symbolic link could be shipped to users while checksums still
matched that unsafe archive, risking writes outside the extraction directory in a vulnerable
extractor.
```

Before the fix, `tools/release.py` checked that a ZIP was non-empty, readable, uncorrupted, and
contained its executable entry, but did not validate every member path or symbolic-link target.

The validator now rejects traversal, absolute paths, Windows drive paths, UNC paths, control
characters, unsafe separators, Windows reserved device names, trailing dots/spaces, overlong
components, case/Unicode collisions, and escaping symbolic links. It bounds member count and
expanded size. Safe macOS `ditto` resource metadata and relative links that remain within their
archive root are allowed. Harmless tests cover each boundary in `tests/unit/test_release_tools.py`.

## Fixed validation gap: inaccurate or substituted SBOM metadata

Classification: confirmed release-integrity validation gap; not a runtime vulnerability.

```text
Source
Stale, malformed, or substituted SBOM.json
↓
Path
metadata generation → asset validation → draft upload
↓
Security boundary
The published SBOM must identify this release and its constrained application dependencies
↓
Impact
Users could receive a structurally valid but misleading inventory with missing or invented
dependency versions, weakening supply-chain review.
```

The release validator now requires CycloneDX 1.6, the exact SafeInstall version, unique named
components with versions, and exact versions for the critical application dependencies pinned in
`constraints/release-python311.txt`. It rejects an OpenAI component because the portable Alpha
does not include that optional SDK. A generated SBOM from the constrained Python 3.11 metadata
environment was validated end to end. Documentation now states that this SBOM covers that
application dependency environment rather than claiming an exact inventory of the Windows/macOS
bundles or operating-system components.

## Reviewed boundaries

### Archive input

`ArchiveLoader` validates member count, per-file and total expanded bytes, compression ratio,
portable path semantics, Unicode/case collisions, and file type before extraction. ZIP links and
all TAR links/devices are rejected. Files are created exclusively inside a private temporary
directory. Existing traversal, drive, UNC, symlink, collision, and size regressions passed.

Result: capability present by design; no confirmed escape found.

### GitHub input

Only strict public `https://github.com/OWNER/REPOSITORY` URLs are accepted. Git receives a fixed
argument vector with `shell=False`, a `--` separator, hooks disabled, LFS smudging disabled, a
sanitized Git environment, timeout, and checkout limits. The no-Git fallback reads metadata from a
fixed GitHub API host, constructs a fixed codeload URL from a validated commit SHA, rejects
redirects, bounds downloads, and passes the result through `ArchiveLoader`.

Result: network and Git capabilities are expected; no argument-injection, redirect-to-arbitrary-
host, or temporary-directory escape found.

### GUI presentation

Target names, paths, errors, findings, and snippets are presented as plain text or table items and
pass through redaction where they cross the UI boundary. Scans run on a worker thread, UI findings
are bounded, AI defaults off, and local scans do not check a key or use the network. Static About
links are the only intended rich-text links.

Result: no target-controlled HTML execution or silent upload found. Very large permitted scans can
still take time; there is no cancellation button in this Alpha.

### Report export

Exports call the existing Markdown/JSON renderers and their final redaction pass. New files use
exclusive creation with restricted permissions. Existing destinations require explicit UI
confirmation and use a same-directory temporary file plus atomic replacement. Symlink outputs and
non-regular destinations are rejected.

Result: no target-controlled path escape or silent overwrite found. A user who explicitly chooses
an untrusted shared directory remains responsible for that destination's local filesystem policy.

### Release supply chain

Actions are pinned to full commit SHAs. Critical Python 3.11 runtime, build, Qt, PyInstaller, and
CycloneDX dependencies are constrained. Build/metadata jobs are read-only; only the tag-only
publish job receives `contents: write`. Manual dispatch does not publish. Final ZIPs are combined
in one metadata job, checksummed, verified with the SBOM, uploaded to a private draft, downloaded,
and verified again before publication.

Result: no blocking permission or stale-asset path found after hardening.

## SafeInstall self-scan

`safeinstall scan .` completed without executing repository content. At review time it reported
180 findings and an overall `CRITICAL` rating. The high-level result is expected for a security
scanner repository and was not treated as proof of a vulnerability:

- `SI-SEC-004` matched an inert private-key-shaped redaction fixture; output was redacted.
- `SI-PY-001`, `SI-NPM-001`, and prompt rules matched the documented inert risky example/tests.
- `SI-PY-006` matched `yaml.load(..., Loader=yaml.BaseLoader)`; `BaseLoader` deliberately constructs
  only basic scalar/collection data and is used inside a strict schema boundary.
- file, subprocess, network, environment, and deletion capabilities belong to safe loaders,
  optional AI, export cleanup, and security tests.
- `GH_TOKEN` matches were GitHub's ephemeral expression in the tag-only publish steps, not a stored
  product secret. Workflow tests enforce the job-level permission boundary.
- development dependency ranges remain intentionally flexible; the release build uses the pinned
  constraints file.

The scanner rules were not weakened to hide these contextual findings.

## Residual risk

- Windows and macOS binaries are unsigned; macOS is not notarized. Users must rely on GitHub TLS,
  the published checksums, and repository provenance.
- Constraints fix versions but not wheel hashes and do not make builds bit-for-bit reproducible.
  Hosted runner images, PyPI, operating-system libraries, and pinned Action commits remain trusted
  supply-chain inputs.
- The SBOM describes a constrained Python application dependency environment generated on Linux;
  it is not an inventory of exact Windows/macOS binary contents, OS libraries, or every opaque
  binary component.
- Static analysis has false negatives and false positives and does not certify software as safe.
- Parser limits reduce denial-of-service risk but cannot eliminate all CPU or memory pressure from
  adversarial inputs.
- There is no telemetry, automatic updater, execution sandbox, Windows Authenticode signature,
  Apple Developer ID signature, or notarization in this Alpha.
