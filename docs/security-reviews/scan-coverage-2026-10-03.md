# 扫描完整性修复记录

日期：2026-10-03。本次改动基于本地 Alpha.2 开发分支 `4607df1`，未修改发布版本或发布资产。

## 问题与结果

文件发现阶段原来会静默跳过超过 2,000,000 字节、无法解码或无法读取的源文件。
核心随后仍对空结果评分，可能返回 `files_scanned=0`、`info`、0 分；桌面界面又把
`info` 显示成绿色“低风险”。目录中只有部分文件可读时，也没有具体遗漏信息。

现已将文件发现结果与扫描覆盖情况一并传入报告：

- 没有任何可扫描文本时抛出 `NoScannableFilesError`，命令行退出码为 2，不生成零分报告。
- 部分扫描保留已发现的风险，并明确显示“扫描不完整”、跳过的路径及原因；命令行在输出
  报告后返回 3。普通扫描完成仍返回 0，不以风险等级决定退出码。
- JSON Schema 升为 1.1，增加 `coverage`。跳过计数准确保留，路径明细最多记录 100 项。
- 中文、英文、技术详情、终端与 Markdown 均说明结果只覆盖已扫描的文件。未知能力不再
  显示为确定的“否”，部分扫描的低分结果不再显示绿色低风险结论。

`complete` 只指受支持格式在配置范围内已读取，不包括本就排除的依赖、构建目录和
不支持的文件格式，也不构成安全保证。无法遍历的目录按一个跳过路径计数，不猜测其文件数。

## 本地安全自查

- 未放宽读取、遍历、归档或解析上限；文件仍最多读取单文件上限加一字节以判断超限。
- 文件及目录链接、重解析点继续不跟随；权限错误和遍历失败会进入覆盖诊断。
- 明细只保存脱敏的相对路径和固定原因码，不记录文件内容或系统异常中的额外数据。
- 展示时继续脱敏；Qt 使用纯文本，终端使用 Rich `Text`，Markdown 路径转义 HTML 及表格
  分隔符。新增回归覆盖这些路径的凭据遮蔽和文本渲染。
- 无源文件时在扫描器、插件和可选 AI 之前终止。本次验证没有启用 AI，也没有执行样本。
